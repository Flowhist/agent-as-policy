# 仓库维护

## 内容归属

| 内容 | 策略 |
| --- | --- |
| 稳定源码、测试、配置、操作说明 | Git 维护 |
| 一次性且已完成的危险动作入口 | 源码移入 `scripts/archive/`，拒绝直接运行，保留审阅与离线测试 |
| 最新硬件状态 | 只在精简接手指南维护一份，注明时间与证据 |
| 已完成任务 | `docs/records/<日期>/`，总结、关键原始日志、结果图片、必要标定快照 |
| 旧方案/逐次接手笔记 | `docs/archive/`，明确历史性质，不覆盖当前入口 |
| 原始 RGB、计划、逐次反馈与诊断 | `captures/`、`logs/runs/` 本机保留，默认 Git 忽略 |
| Python/pytest 缓存 | 可再生，清理，不提交 |
| SDK 二进制、虚拟环境、凭据 | 不提交，不因仓库整理而删除 |

## 2026-10-06 整理范围

新增根 README、agent 接手约定、脚本索引和首次完整抓放记录；原开发 README 保留兼容入口，旧内容和长篇接手笔记归档。保留本轮顶面识别、起点核对、抓取、观察与放置代码及测试，将固定场景的朝向补正/路线搜索/放置执行归档。

`logs/runs/` 原先跟踪的 127 个运行日志退出 Git 索引，**本机文件未删除**。新产生的数百条查询日志也留在本机，不再淹没 Git 状态。精选抓取、放置、最终夹爪日志在 `docs/records/2026-10-06/`。历史版本中的旧日志仍可通过 `git show c44420a:logs/runs/<文件名>` 查看；仅新克隆不会获得所有本机实验原件。

完整标定原件、执行尝试标记、原始照片、失败路线和当前环境保留，以免破坏追溯、重新定位或防重放条件。此次只物理删除可再生的项目 Python/pytest 缓存，不按文件年龄猜测实验数据是否无用。

## 后续整理规则

任务完成后更新接手指南并写一份实验总结；复制少量关键证据，不把每个读状态文件都提交。失败/不确定动作的尝试记录不得删除后重试。迁移机器时除 Git 外还需显式迁移原始标定照片、SDK 二进制与仍在使用的本机上下文。

运行相关离线测试和 `git diff --check` 后再提交。历史 Markdown 可引用仅本机存在的原始证据；当前 README 和实验记录应优先链接版本化资料。重构脚本路径时同步检查调用点和测试，不为整理而连接或操作机器人。
