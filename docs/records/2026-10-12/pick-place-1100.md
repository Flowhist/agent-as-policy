1. 完成结果及时交付：completed 后直接输出最终结果，必要记录一次性生成，避免先改 README、再修生成器描述、再修 geometry。此回合审核后增加了 137.7 s 的用户等待，物理效果没有变化。
2. 全程预检产出可消费的分段结果：明确抓取/松爪/审核边界，保留各段终点 fine，执行前核对实际起点、工具、负载和场景后复用；不匹配才重算。不能直接执行整条 preflight 来跨过夹爪动作。当前接口只能从实读起点规划，缺少这种分段复用，因此 agent 现有重复步骤有接口原因。可优先用轻量全程可达性筛选配合一次最终分段检查，或实现分段预检结果，不必增加服务。
3. 在同一 SDK 会话批量筛选候选落点/高度/姿态：先检查难点及通行可达性，选中后进行完整密集检查。当前两次失败计算只花 15.1 s，流程消耗却达 79.3 s；重点是减少模型逐次改脚本、重启整份计划的交接，不是删掉 IK 检查。成功姿态不能硬编码成下次现场默认。
4. 简化上下文入口和输出：提供网页机器人断开这一明确入口，避免为交出控制权重启全部服务、重新连接传感器；文档只读最短必需部分。run_plan 在 needs_review 返回当前证据/review_id/日志路径，completed 返回摘要，历史结果留 JSONL。当前返回整份累计结果，最终恢复即使只显示 500 token 仍被截断。
5. 视觉失败在同一计算入口返回诊断和候选局部图，避免失败后重新加载标定、打印整份标定、再开进程裁图。不要把未经验证的候选当成功；场景算法仍属于任务计算，不注册红块专用工具。若初始候选图可一次准备好，可合并全图与局部的模型检查。
6. 抽出轻量计划组装函数：plan_build.py 的阶段字典、依赖、审核样板反复生成，几何策略和场景坐标仍由 agent 决定。迭代时改数据参数，避免每次改脚本并覆盖所有派生文件。
7. 后续再优化运动：在同速率下比较可达落点与姿态，结合路径误差验证减少不必要执行点；不能将“更少路点”或“更大 zone”直接当无风险提速。此轮少量轮询/播报不是主要阻塞，不应把其与后台运动的重叠时间再算一次。
