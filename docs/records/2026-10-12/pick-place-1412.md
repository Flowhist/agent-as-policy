## 优化优先级

1. 抽出轻量通用计划组装函数，接收阶段、工具参数、local/model 条件和证据；agent 继续负责场景几何与策略。避免每次重写 Schema 样板、先构造不适用字段再覆盖、修生成器和反复读契约。前置 138.7 s 是首要可压缩项，视觉算法只有 0.218 s，继续优化图像算法本身收益很小。
2. 优化任务路径长度，尤其退出终点与搬运高度。基于障碍和可视要求选最近的合格退出位置，不默认返航。候选筛选先以 IK 关节行程排序，再对选中路线做密集 FK；需避免每个候选都做全量检查而抵消收益。不能无依据统一降低高度或改变抓持朝向。
3. 审核请求一返回就取证、判定、恢复，取消中间 tail 与另一次短轮询。携物看图前等待约 28 s、最终看图前约 17 s，共约 45 s；这是交接延迟，不是必要的图像理解时间。保留动作后两次验收，不靠删证据提速。
4. FK 优化应先定位约 42 ms/唯一采样点的摊销来自 SDK、通信还是调用开销，再考虑本地可信 FK 或有误差界的自适应检查；保持工具/基座/负载/标定一致性。不要直接放宽 0.1°采样，并注意反馈保护也使用检查轨迹。当前缓存已有效，但不同插值点使精确键缓存收益有限。
5. 修正计时口径：从请求开始，到 completed 和最终回复分别报告。等待后台任务用合适的长等待并及时接结果；不要把轮询时间重复算入瓶颈，也不要让统计日志阻塞最终验收提交。

本轮预检、机械臂、夹爪与观测工具合计约 251.5 s，即使其余交接全压缩，五分钟也只剩约 48.5 s 给初始场景与两次审核。稳定达标需要同时减少路线/FK工作和 agent 前置与审核交接，单纯收紧 prompt 或少几个路点不足以保证。
