## 运动脚本与已知问题

- `scripts/cartesian_step.py` 是旧高位对齐的单轴平移工具，workspace 为 x [0.23,0.30]、y [-0.60,-0.40]、z [0.125,0.15] m，单步 0.1~10 mm、1% 速率、每轴变化上限 3 度；不要直接套用任意新任务，更不能把上限扩大当成路径验证。
- `scripts/orientation_joint_step.py` 为已检查的指定关节路线执行单段，`--rate` 允许 0.01~0.10，默认 0.01，每段不超过 5 度，核对起点、FK、关节与 TCP 范围，停稳后下电。现在必须显式指定 `--route`；执行前拒绝 `captures/grasp-orientation-plan/` 内的历史路线，也按规范化 JSON 摘要拒绝两份旧路线的改名/复制版本。新动作须在新目录重新规划；这项防误重放检查不代替新路径验证。它不是通用运动规划器，也不是下降脚本。
- `captures/grasp-orientation-plan/plan.yaml`、`ik-input.json`、`joint-route-search.json` 保留错误 Y 轴假设的历史。有效的修正执行记录为 `corrected-ik-input.json`、`corrected-ik-results.json`、`corrected-joint-route.json`；修正路线已经完整执行，不能从第 0 点重放。
- `plan_grasp_orientation.py` 现默认开合轴 X，但会覆盖同目录规划产物；`correct_grasp_opening_axis.py` 是本次补正专用工具，也会生成文件。接手时保留历史证据，在新目录规划新动作，不要为“恢复上下文”直接重新运行这些生成器。
- 原笛卡尔移动确曾触发 J5 接近零位的奇异点保护，不是单纯 J4 到上限。也曾触发自行设置的单步 3 度关节限制，两者不要混为一谈。改用经过检查的关节路线成功通过 J5 零位，未关闭控制器保护。
- `stop()` 是异步操作；先等待 operationState 为 idle，再下电，否则控制器可能拒绝。MoveAbsJ 的指令应在上电后加入，先加入再上电曾导致 `move empty cache`。失败后先读反馈和原因，不盲目重试。
- SDK 矩阵目标先经 `utility.transArrayToPosture` 转为六维姿态再构造 `CartesianPosition`，不要假定矩阵构造器正确填充逆解需要的字段。矩阵转换使用 SDK utility。`calcAllIkSolutions` 不适用于此机型；confData 不能当作通用二值构型标记。
