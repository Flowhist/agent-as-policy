# 物块顶面定位

2026-10-06：替换将整个红色轮廓当作顶面的旧逻辑。工具 TCP 继续使用用户实测确认的法兰 Z 偏移 248 mm，本次不改动工具参数。

`scripts/block_top.py` 使用红色区域寻找候选目标，但不使用其轮廓中心输出抓取点。通过 OpenCV 线段检测寻找四条顶面边，将交点按 RealSense 官方去畸变射线与桌面上方 29.61 mm 的平面求交，检查顶面尺寸是否符合 90.23 × 29.86 mm、对边一致性和直角关系。中心取三维顶面四角平均，长轴也只由顶面求得。

每条边要求足够的图像边缘支持，顶面内部要求基本无遮挡；斜视时靠相机的顶面边外侧还需有可见红色侧面，避免把物块底部外轮廓当顶面边。尺寸、遮挡或多解检查不通过即拒绝，不回退到整体轮廓，也不输出历史中心。阈值是针对当前已知尺寸红色长方体的几何筛选，不是任意物体的通用分割器，也不保证毫米级实物精度。

纯离线定位，不连接硬件：

```bash
python3 scripts/block_top.py --image captures/example.jpg --output captures/top-check-new
```

默认 ROI 为原始 1280×720 图像的 `[0,500,1280,220]`，可用 `--roi x y width height` 指定；ROI 只限制检测范围，不裁剪坐标或改变内参。输出目录必须不存在。保存 `top-face.json`、`top-mask.png` 和 `top-overlay.jpg`；拒绝时 JSON 只有拒绝原因等信息，没有目标坐标，掩膜为空。

`plan_grasp_orientation.py` 已接入同一检测器，要求 `--output` 指定新目录，拒绝覆盖历史规划。可追加 `--vision-only` 只输出顶面结果，不连接 SDK。检测失败会在 SDK 子进程启动前退出。成功时规划报告包含顶面中心，但该脚本仍只规划朝向，不自动执行水平对齐或下降。

验证使用合成图像测试可见侧面不同厚度、边界缺失、夹指遮挡、多目标歧义和标定坐标转换。清晰历史照片 `captures/task-ready-20261004T031906Z.jpg` 检出顶面，当前遮挡照片 `captures/20261005-233647-591191-0400.jpg` 拒绝输出中心；历史照片中的物块位置不能作为当前目标位置使用。暂定桌面平面和标定误差仍需计入后续定位误差预算。
